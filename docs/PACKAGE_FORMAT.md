# Формат ZIP-пакета викторины

## Структура

Экспорт создаёт архив `<slug>.zip`:

```text
<slug>.zip
├── <slug>.json
└── assets/
    └── <slug>/
        ├── images/
        │   └── <uuid>.webp
        └── media/
            ├── <uuid>.webm
            └── <uuid>.mp4
```

В корне разрешён ровно один JSON и каталог `assets/`. В пакет попадают только
ассеты, на которые ссылаются вопросы и правильные ответы. Конфиг соответствует
`schemaVersion: 1`, описанному в [QUIZ_CONFIG.md](QUIZ_CONFIG.md).

## Манифест целостности

Поле `packageIntegrity` находится внутри JSON:

```json
{
  "algorithm": "sha256",
  "assets": [
    {
      "path": "assets/example/images/image.webp",
      "sha256": "<64 hex symbols>",
      "size": 12345
    }
  ],
  "contentDigest": "<64 hex symbols>"
}
```

`assets` фиксирует путь, размер и SHA-256 каждого изображения или медиафайла.
`contentDigest` связывает канонизированный конфиг с полным отсортированным
списком файлов. Поэтому импорт обнаруживает изменение вопроса, ответа, пути,
размера или содержимого ассета. Хеши подтверждают неизменность пакета,
но не устанавливают автора и не заменяют цифровую подпись.

## Проверка импорта

Сервер сначала проверяет архив целиком, не меняя библиотеку:

1. размер ZIP — не более 500 МБ;
2. не более 200 записей и 1000 МБ после распаковки;
3. один корневой JSON, обязательный `assets/`, отсутствие лишних файлов;
4. отсутствие абсолютных путей, `..`, обратных слешей, дублей и symlink;
5. защиту от аномального коэффициента сжатия;
6. Zod-схему конфига и соответствие имени JSON полю `slug`;
7. фактический формат и допустимость каждого изображения, аудио и видео;
8. точное совпадение ссылок, файлов, размеров, SHA-256 и `contentDigest`.

После успешной проверки импорт устанавливается через временный каталог. При
ошибке существующие конфиг и ассеты возвращаются на место.

## Конфликты

- `error` — остановить импорт и показать выбор пользователю;
- `replace` — заменить викторину с тем же slug и идентификатором;
- `copy` — создать новые UUID, свободный slug и переписать пути ассетов.

Архивы следует переносить как бинарные файлы, не распаковывая и не редактируя.
