# Архитектура приложения «Свояк»

## Назначение

«Свояк» — локальное многопользовательское веб-приложение. Компьютер ведущего
одновременно запускает сервер, хранит викторины и обслуживает интерфейсы
ведущего, игроков и публичного экрана.

## Процесс и сеть

Приложение запускается одним Node.js-процессом через `server.ts`.

```text
server.ts
└── Next.js application
    └── Node.js HTTP server (0.0.0.0:<PORT>)
        ├── Next.js UI и Route Handlers
        └── Socket.IO
```

Порт берётся из переменной окружения `PORT` и по умолчанию равен `3000`.
После запуска сервер выводит адрес `localhost` и доступные локальные IPv4.
`SIGINT` и `SIGTERM` закрывают Socket.IO и Next.js перед завершением процесса.

## Границы модулей

```text
src/
├── app/          маршруты App Router и layouts
├── components/   переиспользуемые UI-компоненты
├── features/     функциональные модули интерфейса
├── server/       код, выполняемый только на сервере
├── shared/       типы, схемы и контракты для клиента и сервера
├── stores/       клиентские Zustand-хранилища
└── styles/       глобальные и обоснованные нестандартные стили
```

Клиентский модуль с директивой `"use client"` не может импортировать
`src/server/`. Это ограничение проверяет архитектурный тест. Сервер остаётся
единственным источником истины игрового состояния.

## Пользовательские данные

Конфиги викторин хранятся в `games/*.json` через серверный `QuizRepository`.
Запись выполняется атомарно, имена строятся только из проверенного slug, а
операции не могут выйти за пределы `games/`. Проверенные и нормализованные
изображения находятся в `games/assets/<quiz-slug>/images/`. При изменении slug
каталог переносится, а при сохранении и удалении очищаются неиспользуемые
файлы.

## Комнаты и Socket.IO

Комнаты находятся в памяти одного процесса в `RoomManager`. Комната содержит
токен ведущего, игроков с индивидуальными токенами, неизменяемый снимок
выбранной викторины, игровую сессию и текущее окно нажатия. После перезапуска
сервера комнаты не восстанавливаются.

Все входящие Socket.IO payload проверяются Zod-схемами из
`src/shared/schemas/`. Типизированные контракты находятся в
`src/shared/contracts/socket.ts`.

```text
Клиент → сервер
├── room:create
├── room:check
├── room:join
├── host:reconnect
├── player:reconnect
├── buzzer:open
├── buzzer:close
├── buzzer:reset
├── buzzer:press
├── session:start / session:finish
├── question:select / question:finish
├── answer:judge
└── score:confirm / score:cancel

Сервер → клиент
├── host:state
├── player:state
└── error
```

Каждое окно нажатия имеет UUID и серверные временные метки. RoomManager
атомарно принимает только первое допустимое событие. Старое, повторное,
просроченное или отправленное после определения победителя событие
отклоняется. Клиентская блокировка улучшает интерфейс, но не участвует в
определении победителя.

Отключившийся игрок остаётся в комнате и может восстановиться по токену из
`localStorage`. Неактивные комнаты без подключённых клиентов периодически
удаляются.

## Доменная модель викторины

Первая версия сохраняемого формата описана `QuizConfig` со
`schemaVersion: 1`. Zod-схемы находятся в `src/shared/schemas/quiz.ts`, а
выведенные из них TypeScript-типы — в `src/shared/types/quiz.ts`.

Формат версии 1 обратно совместимо поддерживает текст, изображение или их
комбинацию. Он проверяет UUID, безопасный slug и asset-пути, временные
настройки, порядок раундов и тем, уникальность всех идентификаторов и
уникальные стоимости вопросов внутри каждой темы. Полное описание и пример
находятся в `docs/QUIZ_CONFIG.md`.

## Медиа и пакеты

Загрузка изображения проходит проверку фактического MIME через `file-type`,
декодирование и ограничение пикселей через `sharp`, после чего файл
нормализуется в WebP под новым UUID. Клиент никогда не задаёт серверное имя
файла.

Экспорт включает один `<slug>.json`, каталог `assets/` и только используемые
изображения. `src/server/package/integrity.ts` канонизирует JSON и вычисляет
SHA-256 каждого файла и общий `contentDigest`.

Импорт сначала полностью проверяет ZIP без изменения библиотеки: размер,
число файлов, корневую структуру, пути, дубликаты, symlink, коэффициент
сжатия, Zod-схему, изображения и все хеши. После проверки данные сохраняются
через временный каталог с откатом при ошибке. `unzipper` настроен как
server-only external package.

## Интерфейс

Корневой layout занимает `100dvh` и запрещает прокрутку документа. Прокрутка
разрешена только во внутренних ограниченных областях через `ScrollArea`.
Основные стили реализуются Tailwind CSS. Анимация нижнего прогресс-бара
изолирована в `src/styles/bottom-progress.css`.

Маршрут `/library` управляет сохранёнными викторинами, `/editor/new` и
`/editor/[quizId]` используют Zustand-черновик, а `/host` объединяет лобби,
игровую сетку и управление фазами. Сервер остаётся единственным источником
счёта, сыгранных вопросов и допустимых переходов.

## Проверки

- TypeScript — строгая проверка типов.
- ESLint — Next.js, React, TypeScript, неиспользуемые импорты, Promise и порядок
  импортов.
- Prettier — единое форматирование и сортировка Tailwind-классов.
- Vitest и Testing Library — unit- и компонентные тесты.
- Playwright — end-to-end сценарии.

Команда `npm run check` объединяет typecheck, lint, проверку форматирования и
unit-тесты.
