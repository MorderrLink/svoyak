# Socket.IO-контракт

Единый типизированный контракт находится в
`src/shared/contracts/socket.ts`, а Zod-схемы входных payload — в
`src/shared/schemas/socket.ts`. Клиент отправляет намерение, сервер проверяет
его и единолично изменяет игровое состояние.

## Клиент → сервер

| Событие               | Роль    | Назначение                                 |
| --------------------- | ------- | ------------------------------------------ |
| `room:create`         | ведущий | создать комнату по `quizId`                |
| `room:check`          | гость   | проверить существование комнаты            |
| `room:join`           | игрок   | войти по коду и имени                      |
| `host:reconnect`      | ведущий | восстановить роль по host token            |
| `player:reconnect`    | игрок   | восстановить роль по player token          |
| `player:ping`         | игрок   | измерить задержку до сервера               |
| `player:telemetry`    | игрок   | передать измеренный ping ведущему          |
| `room:attach-display` | экран   | подключить публичный экран                 |
| `session:start`       | ведущий | начать выбранную викторину                 |
| `round:change`        | ведущий | открыть предыдущий или следующий раунд     |
| `theme:explain`       | ведущий | показать пояснение выбранной темы          |
| `question:select`     | ведущий | выбрать несыгранный вопрос                 |
| `media:restart`       | ведущий | запустить медиа вопроса с начала           |
| `media:stop`          | ведущий | переключить паузу медиа вопроса            |
| `buzzer:open`         | ведущий | вручную открыть окно нажатий               |
| `buzzer:press`        | игрок   | добавить нажатие в очередь текущего окна   |
| `buzzer:close`        | ведущий | закрыть окно нажатий                       |
| `buzzer:reset`        | ведущий | сбросить состояние кнопки                  |
| `answer:select`       | ведущий | выбрать отвечающего из очереди нажатий     |
| `answer:judge`        | ведущий | предложить результат ответа                |
| `score:adjust`        | ведущий | скорректировать баллы игрока вне вопроса   |
| `player:update`       | ведущий | изменить имя и баллы игрока вне вопроса    |
| `score:confirm`       | ведущий | подтвердить редактируемое изменение баллов |
| `score:cancel`        | ведущий | отменить изменение баллов                  |
| `question:finish`     | ведущий | предложить списание цены со всех игроков   |
| `session:finish`      | ведущий | завершить игру вручную                     |
| `timer:skip`          | ведущий | пропустить таймер текущей игровой фазы     |

Каждое событие получает callback `SocketResult<T>`: `{ ok: true, data }` или
`{ ok: false, error }`. Payload со сторонними полями, неверными UUID, кодами,
границами чисел или отсутствующими токенами отклоняется до бизнес-логики.

## Сервер → клиент

| Событие         | Получатель       | Содержимое                                                        |
| --------------- | ---------------- | ----------------------------------------------------------------- |
| `host:state`    | ведущий          | игроки, диагностика, полное управление и приватные данные вопроса |
| `player:state`  | один игрок       | собственные баллы и состояние кнопки                              |
| `display:state` | публичный экран  | безопасное состояние игры без имён и баллов игроков               |
| `error`         | конкретный сокет | типизированная ошибка                                             |

Текст и изображение правильного ответа отсутствуют в `display:state` до фазы
`answer-reveal`. Во время раскрытия формулировка и изображение вопроса в
публичную проекцию не входят.
`hostComment`, host token и player token не входят в публичные состояния.
После `question:finish` сервер создаёт общее предложение изменения счёта.
Одинаковое списание применяется к зафиксированному списку игроков только
после `score:confirm`; `score:cancel` возвращает игру к новому окну нажатий.
`player:update` доступен только в лобби, на сетке, между раундами или после
завершения игры; во время активного вопроса сервер отклоняет команду. Имя
нормализуется, не может быть пустым или длиннее 20 символов и должно быть
уникальным без учёта регистра. `score:adjust` сохранён в контракте для
совместимости старых клиентов.

`theme:explain` переводит игру из сетки в фазу `theme-explanation` без
таймера. Публичный экран получает название и описание темы. Команда
`timer:skip`, вызываемая ведущим по Space, возвращает игру к сетке.

После завершения `question-intro` сервер автоматически создаёт
`mediaPlayback` для аудио- или видеовопроса. Поля `positionMs`, `revision` и
`startedAt` синхронизируют ведущего и публичный экран. `media:stop` переключает
паузу с сохранением текущей позиции и продолжением с неё, а `media:restart` в
любой момент запускает клип от сохранённой левой границы.

## Безопасность и переподключение

Host/player token — UUID, выдаваемые сервером и хранящиеся в браузере. События
ограничены rate limit на сокет и игрока; повторные нарушения приводят к
cooldown и отключению. Клиент передаёт `buzzWindowId`, чтобы запоздалое
нажатие не попало в новое окно.

Состояние комнаты после каждого изменения рассылается заново. Клиент может
безопасно переподключиться, пока серверный процесс работает. После перезапуска
сервера комнаты не восстанавливаются.

`room:join` доступен только до `session:start`. Существующий player token
можно использовать для `player:reconnect` и после начала игры.

Устройство определяется сервером из проверенного User-Agent с доступной
браузеру точностью. Результат `player:ping` клиент измеряет как round-trip и
передаёт через `player:telemetry`. Время подключения, устройство и ping входят
только в приватный `host:state`.

`buzzer:press` не назначает отвечающего и не закрывает окно. Сервер сохраняет
уникальные нажатия в порядке получения и передаёт ведущему готовые позиции.
Только `answer:select` переводит выбранного нажавшего игрока в фазу ответа.
После неверного ответа то же окно нажатий переоткрывается с сохранённой
очередью. Ответивший остаётся в ней для отображения истории, но сервер
отклоняет его повторный выбор.
