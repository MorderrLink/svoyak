# Техническая спецификация приложения «Свояк»

**Редакция:** 3
**Тип:** локальное многопользовательское веб-приложение
**Архитектура:** монолитный Next.js-проект с собственным Node.js-сервером
**Основной язык:** TypeScript

---

# 1. Терминология

## 1.1. Викторина

**Викторина** — заранее созданный набор раундов, тем, вопросов, правильных ответов, комментариев ведущего, настроек времени и изображений.

Викторина существует независимо от игровой комнаты.

Она может быть:

- создана;
- отредактирована;
- сохранена;
- продублирована;
- удалена;
- экспортирована;
- импортирована;

без запуска игровой комнаты и без подключения игроков.

## 1.2. Игровая сессия

**Игровая сессия** — конкретное прохождение выбранной викторины игроками.

Сессия содержит:

- комнату;
- ведущего;
- подключённых игроков;
- текущие баллы;
- выбранную викторину;
- текущий раунд;
- использованные вопросы;
- текущий вопрос;
- историю ответов.

## 1.3. Комната

**Комната** — временное сетевое пространство, к которому игроки подключаются по коду, ссылке или QR-коду.

## 1.4. Экран ведущего

Приватный интерфейс управления игровой сессией.

На нём отображаются:

- комментарий ведущего;
- правильный ответ;
- управляющие кнопки;
- состояние игроков;
- операции с баллами;
- служебная информация.

## 1.5. Публичный экран

Отдельный полноэкранный интерфейс, предназначенный для телевизора, проектора или второго монитора.

На нём отображаются:

- игровая сетка;
- выбранная тема и стоимость;
- формулировка вопроса;
- изображение вопроса;
- имя отвечающего игрока;
- правильный ответ после раскрытия;
- итоговые результаты.

---

# 2. Разделение создания и прохождения викторины

Создание викторины и проведение игровой сессии являются двумя независимыми режимами приложения.

## 2.1. Режим библиотеки и редактора

Ведущий может в любое время запустить приложение и:

1. открыть библиотеку викторин;
2. создать новую викторину;
3. указать её название;
4. добавить раунды;
5. добавить темы;
6. добавить вопросы;
7. назначить стоимость вопросов;
8. добавить правильные ответы;
9. добавить комментарии ведущего;
10. загрузить изображения;
11. настроить временные интервалы;
12. сохранить викторину;
13. экспортировать её в ZIP.

Для этого не создаётся игровая комната и не запускается игровая сессия.

## 2.2. Режим проведения викторины

Для проведения игры ведущий:

1. создаёт комнату;
2. выбирает одну из ранее созданных или импортированных викторин;
3. получает код, ссылку и QR-код;
4. ожидает подключения игроков;
5. при необходимости открывает публичный экран;
6. запускает игровую сессию.

После запуска комнаты редактор викторины не используется.

## 2.3. Снимок викторины

При запуске игровой сессии сервер создаёт неизменяемый снимок выбранной викторины.

Изменения исходной викторины после запуска комнаты не должны менять уже начатую игровую сессию.

# 3. Локальная сетевая модель

Компьютер ведущего одновременно является:

- сервером;
- хранилищем викторин;
- интерфейсом ведущего;
- источником публичного экрана.

Все устройства подключаются внутри одной локальной сети.

```text
Wi-Fi-роутер
├── Компьютер ведущего и сервер
├── Телефон игрока 1
├── Телефон игрока 2
├── Телефон игрока 3
└── Телевизор через HDMI как второй экран
```

Пример адреса сервера:

```text
http://192.168.1.50:3000
```

Пример ссылки на комнату:

```text
http://192.168.1.50:3000/join/A7K4
```

Интернет для проведения викторины не требуется.

# 4. Подключение игроков

Игрок может подключиться тремя способами.

## 4.1. По ссылке

```text
http://192.168.1.50:3000/join/A7K4
```

Код комнаты уже содержится в ссылке.

## 4.2. По QR-коду

QR-код содержит полную локальную ссылку.

После сканирования открывается страница ввода имени.

## 4.3. По коду

Игрок открывает главную страницу приложения и вводит код:

```text
A7K4
```

После подключения браузер сохраняет токен игрока для возможного переподключения.

Используется:

- Next.js App Router;
- React;
- TypeScript;
- Route Handlers;
- Server Components;
- Client Components.

## 5.2. Socket.IO

Socket.IO подключается к тому же HTTP-серверу, который обслуживает Next.js.

```text
Один адрес и один порт
├── Next.js UI
├── HTTP API
├── изображения

```

## 5.3. Собственный сервер

Файл:

```text
server.ts
```

Отвечает за:

- запуск Next.js;
- создание HTTP-сервера;
- привязку к `0.0.0.0`;
- запуск Socket.IO;
- поиск локального IP;
- создание менеджера комнат;
- корректное завершение процесса.

Концептуальная структура:

```ts
const nextApp = next({ dev });
const requestHandler = nextApp.getRequestHandler();

const httpServer = createServer((request, response) => {
  requestHandler(request, response);
});

const io = new Server(httpServer);

httpServer.listen(port, "0.0.0.0");
```

В него входят:

- перечисления;

`src/server/` содержит только серверную логику:


Модули из `src/server/` запрещено импортировать в клиентские компоненты.

# 8. Викторина

## 8.1. Основная структура

```ts
interface QuizConfig {
  schemaVersion: number;

  id: string;
  title: string;
  slug: string;

  settings: QuizSettings;
  rounds: QuizRound[];

  packageIntegrity: PackageIntegrity;

  createdAt: string;
  updatedAt: string;
}
```

## 8.2. Настройки

```ts
interface QuizSettings {
  questionIntroSeconds: number;
  buzzSeconds: number;
  answerSeconds: number;
  answerRevealSeconds: number;

  allowNegativeScore: boolean;
  showScoresToPlayers: boolean;
}
```

### `questionIntroSeconds`

Задержка между выбором вопроса и его отображением.

Значение по умолчанию:

```text
2,5 секунды
```

### `buzzSeconds`

Количество секунд, в течение которых кнопки игроков активны.

### `answerSeconds`

Визуальное время, отведённое отвечающему игроку.

Истечение этого времени не определяет автоматически правильность ответа.

### `answerRevealSeconds`

Продолжительность показа правильного ответа на публичном экране перед возвращением к сетке.

# 9. Раунды

Раунды не имеют пользовательских названий.

```ts
interface QuizRound {
  id: string;
  order: number;

```

В интерфейсе они автоматически называются:

```text
Раунд 1
Раунд 2
Раунд 3
```

Название не сохраняется в конфиге.

# 10. Темы

```ts
interface QuizTheme {
  id: string;
  title: string;
  order: number;
  questions: QuizQuestion[];
}
```

Вопросы внутри одной темы должны иметь уникальную стоимость.

Пример:

```text

├── 100
├── 200
├── 300
├── 400
└── 500
```

Разные темы могут иметь разные наборы стоимостей.

# 11. Вопросы

```ts
interface QuizQuestion {
  id: string;
  price: number;

  content: QuestionContent;

  answer: string;
  hostComment?: string;
}
```

## 11.1. Содержимое

```ts
interface QuestionContent {
  text?: string;
  image?: QuizImage;
}
```

```ts
interface QuizImage {
  path: string;
  alt?: string;
}
```

Вопрос может содержать:

- только текст;
- только изображение;
- текст и изображение.

Хотя бы одно поле `text` или `image` обязательно.

## 11.2. Правильный ответ

`answer` обязателен и виден только ведущему до момента раскрытия.

## 11.3. Комментарий ведущего

`hostComment` является необязательным приватным полем.

Пример:

```json
{
  "price": 200,
  "content": {
    "image": {
      "path": "assets/muzykalnaya-viktorina/keanu-reeves.webp"
    }
  },
  "answer": "Киану Ривз",
  "hostComment": "Сказать игрокам: назовите актёра на изображении"
}
```

Комментарий:

- не показывается игрокам;
- не показывается на публичном экране;
- отображается только на экране ведущего;
- может существовать даже при отсутствии текста вопроса.

# 12. Управляющие операции редактора

JSON содержит только данные и не содержит методов.

Операции над структурой реализуются отдельным доменным сервисом и действиями Zustand-хранилища.

```ts
interface QuizEditorActions {
  setQuizTitle(title: string): void;

  addRound(): void;
  removeRound(roundId: string): void;
  moveRound(roundId: string, targetIndex: number): void;

  addTheme(roundId: string): void;
  updateTheme(
    roundId: string,
    themeId: string,
    patch: Partial<QuizTheme>,
  ): void;
  removeTheme(roundId: string, themeId: string): void;
  moveTheme(roundId: string, themeId: string, targetIndex: number): void;

  addQuestion(roundId: string, themeId: string): void;
  updateQuestion(
    roundId: string,
    themeId: string,
    questionId: string,
    patch: Partial<QuizQuestion>,
  ): void;
  removeQuestion(roundId: string, themeId: string, questionId: string): void;

  attachImage(
    roundId: string,
    themeId: string,
    questionId: string,
    file: File,
  ): Promise<void>;

  removeImage(
    roundId: string,
    themeId: string,
    questionId: string,
  ): Promise<void>;

  validate(): QuizValidationResult;
  save(): Promise<void>;
}
```

Frontend выполняет предварительную проверку.

Backend повторно проверяет все данные перед сохранением.

# 13. Название и slug викторины

Каждая викторина имеет:

- `title` — отображаемое название;
- `slug` — безопасное имя для файлов и каталогов.

Пример:

```text
Название:
Музыкальная викторина 2026

Slug:
muzykalnaya-viktorina-2026
```

Используется процесс slugification:

1. удаление лишних пробелов;
2. приведение к нижнему регистру;
3. транслитерация кириллицы в латиницу;
4. замена пробелов и разделителей на `-`;
5. удаление неподдерживаемых символов;
6. предотвращение повторяющихся `-`;
7. проверка уникальности.

Используется именно транслитерация, а не смысловой машинный перевод, поскольку приложение должно работать полностью локально.

Пользователь может изменить предложенное имя файла перед экспортом.

# 14. Локальное хранение викторин

Все викторины находятся в каталоге:

```text
games/
```

Структура:

```text
games/
├── muzykalnaya-viktorina.json
├── filmy-i-serialy.json
└── assets/
    ├── muzykalnaya-viktorina/
    │   ├── actor.webp
    │   └── album-cover.jpg
    └── filmy-i-serialy/
        └── movie-frame.png
```

Для викторины:

```text
muzykalnaya-viktorina
```

используются:

```text
games/muzykalnaya-viktorina.json
games/assets/muzykalnaya-viktorina/
```

Все изображения конкретной викторины должны находиться только в её каталоге.

При удалении викторины backend должен предложить удалить и её изображения.

При переименовании slug backend должен атомарно:

1. переименовать конфиг;
2. переименовать каталог изображений;
3. обновить пути в конфиге;
4. сохранить конфиг;
5. откатить операцию при ошибке.

# 15. Экспорт викторины

## 15.1. Структура архива

Каждый экспортируемый архив обязан содержать ровно:

- один JSON-конфиг в корне;
- один каталог `assets/` в корне.

Других файлов и каталогов верхнего уровня быть не должно.

```text
muzykalnaya-viktorina.zip
├── muzykalnaya-viktorina.json
└── assets/
    └── muzykalnaya-viktorina/
        ├── actor.webp
        └── album-cover.jpg
```

Даже если викторина не содержит изображений, пустой каталог `assets/` должен присутствовать.

## 15.2. Предложенное имя

При экспорте предлагается имя:

```text
<slug>.zip
```

Например:

```text
muzykalnaya-viktorina-2026.zip
```

Перед сохранением пользователь может изменить имя.

## 15.3. Системное окно сохранения

При наличии поддержки используется системный диалог сохранения файла.

Fallback:

- приложение создаёт ZIP;
- браузер скачивает его;
- в заголовке ответа задаётся рекомендуемое имя.

# 16. Целостность экспортируемого архива

Требование «неизменности» реализуется через строгую структуру и контрольные суммы.

## 16.1. Строгая структура

Импортируемый архив считается структурно допустимым, только если:

- в корне находится ровно один `.json`;
- в корне находится ровно один каталог `assets`;
- других элементов в корне нет;
- все изображения находятся внутри `assets/`;
- JSON не ссылается на файлы вне `assets/`.

## 16.2. Контрольные суммы

Конфиг содержит список файлов и их SHA-256:

```ts
interface PackageIntegrity {
  algorithm: "sha256";
  assets: AssetChecksum[];
  contentDigest: string;
}
```

```ts
interface AssetChecksum {
  path: string;
  sha256: string;
  size: number;
}
```

`contentDigest` вычисляется из:

- канонизированного конфига без самого `contentDigest`;
- отсортированного списка путей;
- SHA-256 всех изображений;
- размеров файлов.

При импорте все значения вычисляются повторно.

Импорт отклоняется, если:

- файл изменён;
- файл отсутствует;
- присутствует лишний файл;
- размер отличается;
- контрольная сумма отличается;
- конфиг изменён без обновления digest.

Эта проверка обнаруживает случайное изменение или повреждение пакета. Она не является цифровой подписью и не защищает от злоумышленника, который намеренно пересоздаст все хеши.

# 17. Импорт викторины

Импорт выполняется транзакционно.

## 17.1. Этапы

1. Пользователь выбирает ZIP.
2. Backend проверяет размер.
3. Архив открывается без постоянной распаковки.
4. Проверяется структура корня.
5. Находится единственный JSON.
6. Проверяется каталог `assets/`.
7. JSON разбирается.
8. Конфиг проверяется через Zod.
9. Проверяется версия схемы.
10. Проверяются пути.
11. Проверяются форматы изображений.
12. Проверяются размеры файлов.
13. Вычисляются SHA-256.
14. Проверяется `contentDigest`.
15. Архив распаковывается во временный каталог.
16. При успехе данные переносятся в `games/`.
17. При ошибке временные файлы удаляются.

Частично импортированная викторина не должна появляться в библиотеке.

## 17.2. Конфликт slug

Если такой slug уже существует, приложение предлагает:

- заменить существующую викторину;
- импортировать как копию;
- отменить импорт.

При создании копии генерируется slug:

```text
muzykalnaya-viktorina-2
```

Пути изображений и конфиг автоматически обновляются.

## 17.3. Безопасность

Запрещаются:

- абсолютные пути;

```text
.gif
```

# 19. Игровая кнопка

Кнопка является главным элементом интерфейса игрока.

## 19.1. Требования

Кнопка должна:

- находиться в центре;
- занимать большую часть свободного пространства;
- всегда быть видимой;
- не перемещаться при смене состояния;
- не требовать прокрутки;
- поддерживать касание;
- поддерживать мышь;
- поддерживать `Space`;
- поддерживать `Enter`;
- возвращать DOM-фокус после смены игровой фазы.

```ts
buttonRef.current?.focus({
  preventScroll: true,

```

## 19.2. Состояния

```ts
type BuzzerState =
  | "waiting"
  | "intro"
  | "ready"
  | "sending"
  | "winner"
  | "other-player-answering"
  | "answered-incorrectly"
  | "time-expired"
  | "disconnected";
```

## 19.3. После неправильного ответа

Если игрок ответил неправильно:

- его идентификатор добавляется в список ответивших;
- его кнопка отключается до завершения текущего вопроса;
- он не участвует в следующих попытках этого вопроса;
- остальные игроки снова получают активные кнопки.

# 22. Нижний прогресс-бар

## 22.1. Расположение

Прогресс-бар располагается у самого нижнего края экрана.

Он показывается:

- на экране ведущего;
- на публичном экране;
- на экранах игроков.

## 22.2. Внешний вид

Полоска должна:

- иметь небольшую высоту;
- занимать всю ширину;
- не перекрывать контент;
- уменьшаться равномерно от обоих краёв к центру;
- исчезать после завершения соответствующей фазы.

Для уменьшения к центру используется масштабирование относительно центра:

```css
transform-origin: center;
transform: scaleX(var(--progress));
```

## 22.3. Отдельный файл

Стили находятся в:

```text
src/styles/bottom-progress.css
```

В этом файле определяются:

- высота;
- позиционирование;
- transform-origin;
- анимация;
- состояния завершения;
- режим уменьшенного движения.

Остальное оформление выполняется Tailwind-классами.

## 22.4. Виды прогресса

Один компонент используется для:

- задержки перед вопросом;
- времени на нажатие;
- визуального времени ответа;
- времени показа правильного ответа.

# 23. Два экрана ведущего

Поддерживаются два независимых интерфейса.

## 23.1. Панель ведущего

Маршрут:

```text
/host/[roomCode]
```

Содержит:

- приватный комментарий;
- правильный ответ;
- список игроков;
- баллы;
- состояние кнопок;
- имя отвечающего;
- управляющие действия;
- подтверждение баллов;
- ручное завершение фаз.

## 23.2. Публичный экран

Маршрут:

```text
/display/[roomCode]
```

Является read-only клиентом.

Он может быть:

- открыт в отдельном окне;
- перенесён на второй монитор;
- выведен через HDMI на телевизор;
- переведён в полноэкранный режим.

## 23.3. Синхронизация

Оба окна подключаются к одной комнате через Socket.IO.

```text
Комната
├── host-control
├── public-display
├── player
├── player
└── player
```

Публичный экран получает только разрешённые данные.

Он не получает заранее:

- комментарий ведущего;
- правильный ответ;
- токен управления.

Правильный ответ отправляется публичному экрану только после команды раскрытия.

```ts
type GamePhase =
  | "lobby"

  | "score-confirmation"
```

```text

  ↓

  ↓

  ↓

  ↓

  ↓
```

# 25. Выбор вопроса и предварительная задержка

Пример:

Игрок выбирает:

```text
Музыка за 200
```

Ведущий нажимает соответствующую ячейку.

## 25.1. Фаза `question-intro`

Сразу после выбора:

- сетка скрывается;
- начинается задержка, например 2,5 секунды;
- на публичном экране появляется:

```text
Музыка
200
```

- на экране ведущего показываются тема и стоимость;
- кнопки игроков остаются отключёнными;
- снизу показывается уменьшающийся прогресс-бар.

Игроки не видят название темы и стоимость на своих телефонах.

## 25.2. Окончание задержки

После завершения `questionIntroSeconds` сервер одновременно:

1. переводит фазу в `buzzing`;
2. открывает кнопки;
3. запускает время на нажатие;
4. показывает вопрос на публичном экране;
5. показывает вопрос, ответ и комментарий ведущему.

Ведущий сразу начинает читать вопрос.

---

# 26. Время на нажатие

После открытия кнопок запускается `buzzSeconds`.

Сервер передаёт:

```ts
interface TimerState {
  startedAt: number;
  endsAt: number;
  durationMs: number;
}
```

Frontend отображает анимацию.

Сервер определяет, попало ли нажатие во временной интервал.

Если никто не нажал, ведущий может:

- открыть кнопки повторно;
- завершить вопрос;
- раскрыть правильный ответ.

---

# 27. Определение первого нажатия

Первым считается игрок, чьё допустимое событие первым обработал сервер.

Сервер проверяет:

- фазу;
- идентификатор комнаты;
- идентификатор игрока;
- временное окно;
- наличие предыдущего победителя;
- отвечал ли игрок ранее;
- ограничения частоты событий.

После первого допустимого нажатия:

- остальные нажатия отклоняются;
- кнопки блокируются;
- выбранный игрок получает состояние `winner`;
- начинается визуальный таймер ответа.

---

# 28. Время ответа

Таймер ответа является только визуальной подсказкой.

Он не принимает игровых решений.

После его окончания:

- баллы не меняются;
- ответ не считается автоматически неправильным;
- игрок не блокируется автоматически;
- ведущий самостоятельно принимает решение.

Ведущий определяет:

- ответил ли игрок правильно;
- ответил ли игрок неправильно;
- не успел ли игрок;
- нужно ли принять ответ после окончания полоски.

Доступные действия:

```text
Верно
Неверно
Не успел
```

`Не успел` обрабатывается как отдельный результат ответа, но дальнейшую операцию с баллами всё равно подтверждает ведущий.

---

# 29. Подтверждение изменения баллов

Нажатие «Верно», «Неверно» или «Не успел» не изменяет баллы автоматически.

После оценки создаётся предложение операции.

```ts
interface ScoreChangeProposal {
  playerId: string;
  playerName: string;

  judgement: "correct" | "incorrect" | "timeout";

  questionPrice: number;
  suggestedDelta: number;
  editedDelta: number;
}
```

## 29.1. Правильный ответ

Для вопроса стоимостью 500:

```text
Александр ответил верно.

Изменение баллов:
[ +500 ]

[Подтвердить] [Отмена]
```

Ведущий может изменить значение:

```text
+500
+400
+1000
0
```

## 29.2. Неправильный ответ

При включённых отрицательных баллах предлагается:

```text
Александр ответил неправильно.

Изменение баллов:
[ -500 ]
```

Ведущий может изменить значение или поставить `0`.

## 29.3. Не успел

Предлагаемое изменение задаётся настройками викторины.

По умолчанию:

```text
0
```

или:

```text
-price
```

Выбор окончательного значения всегда остаётся за ведущим.

## 29.4. Применение

Баллы меняются только после нажатия:

```text
Подтвердить
```

Результат ответа и операция с баллами являются разными действиями.

Игрок может быть признан ответившим неправильно, но получить изменение `0`.

---

# 30. Правильный ответ

После правильного ответа:

1. ведущий оценивает ответ;
2. подтверждает изменение баллов;
3. сервер завершает вопрос;
4. публичный экран показывает правильный ответ;
5. запускается `answerRevealSeconds`;
6. после завершения времени возвращается сетка.

При необходимости ведущий может пропустить показ ответа вручную.

---

# 31. Неправильный ответ

После неправильного ответа:

1. ведущий выбирает «Неверно» или «Не успел»;
2. подтверждает изменение баллов;
3. игрок добавляется в `attemptedPlayerIds`;
4. его кнопка отключается до конца вопроса;
5. вопрос остаётся на публичном экране;
6. для остальных игроков запускается новый таймер нажатия;
7. остальные игроки снова соревнуются за право ответа.

```ts
interface ActiveQuestion {
  questionId: string;
  attemptedPlayerIds: string[];
  currentPlayerId: string | null;
  buzzAttempt: number;
}
```

Каждая новая попытка имеет новый идентификатор временного окна.

---

# 32. Все игроки ответили неправильно

Если все подключённые и допущенные игроки уже ответили неправильно:

1. кнопки остаются отключёнными;
2. фаза автоматически меняется на `answer-reveal`;
3. публичный экран показывает правильный ответ;
4. запускается время показа ответа;
5. после завершения времени приложение возвращается к сетке.

Ведущий может вручную ускорить переход.

---

# 33. Защита от спама кнопки

Обычный trailing debounce использовать нельзя, поскольку он задерживал бы первое честное нажатие.

Используется комбинация механизмов.

## 33.1. Leading-edge debounce

Первое нажатие отправляется немедленно.

Последующие нажатия временно игнорируются.

```text
Первое нажатие: отправляется сразу
Повторные: блокируются
```

## 33.2. Single-flight lock

После отправки события кнопка переходит в `sending`.

До ответа сервера новое событие не отправляется.

## 33.3. Защита от удерживания клавиши

События с:

```ts
event.repeat === true;
```

игнорируются.

## 33.4. Идентификатор окна

Каждая попытка содержит:

```ts
buzzWindowId;
```

Игрок может отправить не более одного события для одного `buzzWindowId`.

## 33.5. Серверный rate limit

Сервер ограничивает частоту событий для каждого сокета.

Избыточные события:

- игнорируются;
- записываются в журнал;
- при систематическом нарушении временно блокируются.

## 33.6. Преждевременное протыкивание

В поздней версии может быть добавлен штраф за частые нажатия во время закрытой кнопки.

Например, после преждевременного нажатия игрок получает короткий локальный cooldown.

Цель защиты — сделать выгодным точное попадание в момент открытия, а не непрерывное нажатие.

# 39. Критерий готовности версии 1.0

Приложение считается готовым, если пользователь может:

1. запустить приложение без интернета;
2. создать полноценную викторину;
3. добавить несколько раундов;
4. добавить темы и вопросы;
5. использовать текст и изображения;
6. сохранить викторину в `games/`;
7. экспортировать её в проверяемый ZIP;
8. импортировать ZIP на другом компьютере;
9. создать комнату;
10. выбрать ранее созданную викторину;
11. подключить игроков по QR-коду, ссылке или коду;
12. вывести публичный экран на телевизор;
13. провести вопрос с предварительной задержкой;
14. определить первого игрока;
15. самостоятельно оценить ответ;
16. подтвердить изменяемую операцию с баллами;
17. повторно открыть кнопки после неправильного ответа;
18. показать правильный ответ после завершения вопроса;
19. провести все раунды;
20. получить итоговую таблицу.
